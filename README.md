# AI2ScreenWake (ai2sw)

AI2ScreenWake is a macOS idle-protection utility under development, not a released application. PR #11 is merged at `86faea0`; basic keep-awake remains independent of optional corner Accessibility. The transferred branch removes the unsolicited notice, corrects pointer delivery, and adds explicitly requested Accessibility setup without automatic permission challenges. ## Controls and architecture

The explicit “Install active (beyond idle) sleep preventer” selection opens System Settings Accessibility and an app-owned “Drag app icon to panel” instruction window. The icon is a real native file-URL drag of the current application bundle. macOS may still require enabling the app and authentication; a drop or accepted Settings URL never proves a grant. Rust observes actual nonprompting trust only while setup is open and distinguishes it from confirmed optional filter activation. A granted, still-admitted On acquisition can retry only its optional guard without cycling basic assertions; Off remains Off. Close/Off/Toggle/Quit retire setup callbacks, and ordinary menu copy gains no warning or limitation row. This is setup for the existing configured-saver-corner filter, not prevention of arbitrary explicit sleep or security locking.

The host starts Off. Its landscape TV retains two selector dots, an inset screen and equally weighted cabinet/screen outlines; the shorter, lower left antenna has two rays and no horizontal base. Off has closed eyes, a smile and right-side Zzz with a clear pixel above the cabinet. On has large eyes, distinct pupils and one straight mouth; Error has X X eyes and a frown. Visible values are exactly `Mode: Can Sleep`, `Mode: No Sleep` and `Off: Error`. The last is literal display copy, not a claim that independently confirmed protection became Off. Pending retains the last confirmed face/value, with truthful Pending detail in Rust tooltip/accessibility and unchanged nullable core/MCP status. Genuine faults immediately take precedence over intentional previews.

Short primary input toggles once on release, never on down. A native button cell receives the actual tracking Down and release coordinates without interpreting `NSApplication.currentEvent` as that pointer event. It retains AppKit's inherited tracking loop and shares its gesture with the narrow app-local monitor. The 0.45-second timer opens the anchored popover while held, and a held release never toggles. Control-click and right-click also open that popover. Small in-button jitter preserves a hold; deliberate drag, leaving bounds, outside release, keyboard input and disabled/closing rendering cancel it. A gesture-scoped timer observes queued own-process keyboard cancellation without consuming/replaying input. Image-only native drawing and separate programmatic/Accessibility activation remain, without an overlay, custom tracking loop or global input hook. Native tests include forwarded events while AppKit's current event is unrelated; this is not physical/HID acceptance.

Disabling Toggle cancels a press already active at that transition, but new held/Control-primary gestures still open the diagnostic menu without enabling protection. Website completion also remains recoverable if the native input channel is saturated; overflow is explicit and the actual completion preserves the original logged request.

The large 96-point TV remains a keyboard-accessible cycle control: On to Off to Error to On, with real power targets On, Off and Off respectively. Error preview requires its exact successful confirmed-Off settlement, identifies itself in tooltip/accessibility and never creates a core fault or MCP error. Rapid input waits for observed power; newer ordinary admitted controls retire preview transitions, while queries preserve the preview. Neutral initial focus and side-by-side Show Log/Quit remain. The requested wrapping setup action adds 44 points to the former 176 x 168 menu, retaining full artwork, two-point top inset, fitting mode strings and three-point footer margin.

The tiny bottom-left version is the Rust-projected canonical binary version, such as `v2026.11.18(1)`. A blue native top-right information-circle button has accessible help and keyboard focus; explicit activation alone requests `https://ai2sw.info`. Rust logs the typed intent/effect and correlated native outcome, including an explicit error on workspace refusal. Background rendering never opens the site, and no fourth MCP tool is added. Website DNS availability is separate from implementing that fixed target.

On/No Sleep means native-confirmed basic protection with both IOKit idle assertions and current owner/lifecycle admission, including the admitted idle-sleep veto. It works when optional manual-corner Accessibility permission is denied, absent or unavailable. The menu keeps the On face without an optional-corner notice or added row; optional failures stay in the action log, not a fatal MCP error or invented corner success. Actual automatic-screen-saver efficacy still requires a real witness.

The current optional filter is explicitly Accessibility-gated and subscribes only to mouse movement/drag, not keyboard events. Apple's modifying/listen-only tap discussion and keyboard-access documentation are not a general proof about all mouse-only taps or possible corner solutions. Basic idle assertions need no Accessibility grant; this setup does not add Input Monitoring, Screen Recording, Automation or authority over forced sleep/security locks.

The guard redirects original movement/drag only at configured saver corners; known Lock and unknown actions are not selected. Startup, ordinary On, MCP, queries, Off and health checks never request permission; only the explicit setup selection opens the panel. Denial or guard loss leaves independently confirmed basic protection On without adding menu wording. Genuine basic assertion, clock, lifecycle, cancellation and ownership failures remain error-first failures, retaining their current operation's first cause for later queries; explicit Off/retry stays reachable.

Each enabled interval uses a freshly validated corner assignment. Detected relevant configuration/topology changes retire it; unrelated writes resume only after exact revalidation. There is no atomic public transaction with Dock's in-memory settings, so concurrent external reconfiguration retains an unverified interval. Forced sleep/security locks remain available. No preferences, permission bypass, saver/Dock termination or synthetic activity is used. Original-event deflection is not a cancelled IOPM token or a fabricated suppressed-idle record. Signed-app permission, actual Dock prevention, human held-input delivery and automatic screensaver efficacy remain unverified.

AndrewC additionally requires both idle assertions and an explicit idle-sleep veto. The native callback now rejects actual CanSystemSleep requests with `IOCancelPowerChange` only while the current admitted acquisition is ready. Off, stale/unadmitted/retired/lost protection allows sleep; non-abortable WillSleep is always acknowledged with `IOAllowPowerChange`. API/timing failures stay explicit and never emit a successful cancellation or On result. This idle-system-sleep mechanism is not a manual-screen-saver veto and changes no permission policy.

It affects all corners, not only the saver, and has no documented background lease. No Accessibility prerequisite is documented; actual no-grant behavior is unverified. That candidate is not silently selected for this macOS 13+ background utility, and the bounded search is not an impossibility proof.

The completed [community follow-up](<docs/plans/2026-11-15_plan_todo_ScreenWake_Orch.md#community-follow-up-and-coverage-limits>) adds original Stack Overflow/Ask Different evidence: historical YouTube dismissal after manual-corner activation, preference disabling reported effective after Dock reload, and a macOS-15.6 modifier mitigation. The black QuickTime loop is a separate idle anecdote; the accepted JavaScript restore sample is untested and callback-incorrect. Nine Reddit threads were indexed/triaged, but four original reads hit JavaScript challenges and original comments remain unread. Source traces and snippets are not current preactivation/no-grant proof or an exhaustive-web claim. No settings/media/activity/private implementation is selected. The [notification/Dock follow-up](<docs/plans/2026-11-15_plan_todo_ScreenWake_Orch.md#notification-and-dock-investigation>) distinguishes after-start notification source evidence from unverified background Dock dismissal; neither effect is enabled.

Show Log creates or refreshes one bounded private snapshot per owner run at `~/Library/Logs/AI2ScreenWake/yyyyMMdd{DD}HHmmss_ai2sw.log`. The timestamp is local 24-hour time; `DD` is lowercase `mo/tu/we/th/fr/sa/su`. The full actual absolute path is line one, and the read-only viewer uses the actual timestamped basename. The native seam resolves the current user's home and captures one instant; repeated opens refresh that same file only on demand. A collision with another run's filename is an explicit log error, never an overwrite or invented future time.

Below that path, the newest actual entry comes first and older entries follow; omission/storage notices come after entries. Export and viewer share the same bounded 200-label/64-KiB metadata-only formatter. Identical background renders preserve selection/scroll; explicit opening or changed refresh reveals the top. Private 0700/0600 ownership, atomic publication and errors-first behavior stay unchanged. Binary journal/archive append/replay/checksums and login-session lock/socket identity do not reverse. No tailing, automatic clipboard, retention/deletion or external sending is added.

Current readable genus labels have four static typed fields, ending in the verb, such as `Power:Session:Protection:Query` or `Ui:Menu:Presentation:Render`. Compact registry/root/action/instance diagnostics follow separately; no opaque ID is printed per row. One genuine registry-lifetime identity plus checked root ordinals replaces IDs minted for every ordinary root. Real native operation/session/sample identities remain. Old journal rows retain their actual legacy path, explicitly marked `legacy`, without changing stored bytes or replaying protection. IPC negotiates its updated envelope format before controls, refusing older peers explicitly instead of risking mismatched settlement.

Three Rust runtime crates provide backend contracts, client/owner policy, and native OS access. Commands, observations, and errors use Actions; generated UniFFI connects minimal Swift/AppKit rendering. Native UI and MCP share one login-session owner, not separate power assertions. Bounded durable history rebuilds diagnostics after restart, never live On intent or assertions.

## Local build

Build from a clean, committed checkout on an arm64 Mac with Rust, Xcode's command-line tools/macOS SDK, `xcrun`, `codesign`, and `plutil`. MCP/bindgen dependencies require Rust 1.88 or later; the verified toolchain is Rust 1.97.1 and Swift 6.4.2 on macOS 27.0.1. The arm64/macOS 13 deployment target is not a macOS 13 runtime or Intel/universal compatibility claim.

```sh
cargo xtask build --profile release
```

The sole app output is `target/ai2sw/ai2sw.app`, containing executable `ai2sw`, the unchanged MCP executable, thirteen artwork resources and license, nineteen signed files in all. Four SVG masters produce twenty-three encoded assets; each of the three menu masters independently supplies 24/48-pixel menu images and 96/192-pixel previews. The detailed app icon is unchanged. The stable bundle identifier remains `com.appliedmedia.ScreenWake`; no private owner/history identity migrates. Generated bindings, feature snapshots, assets and build evidence share `target/ai2sw/`. The builder verifies current-source provenance, ad-hoc signatures and discovery-only MCP without launching or enabling the app. It does not install, notarize or release it. See [build and check details](<code/xtask/README.md>).

Under its existing exclusive worktree publication lock, the builder captures the host-local calendar once. A verified owned same-day successful bundle advances the revision; a new local day or the recognized legacy `0.1.0` bundle starts at 1. Failed builds consume no revision, worktrees do not consume main's revisions, malformed/future/overflowing predecessors fail explicitly, and tracked source never changes during a build. Compiled FFI/runtime, MCP initialization, footer, generated plist and provenance share the frozen version/stamp. `--build-info` reports it without starting the app/owner; noncanonical Cargo builds explicitly identify as `Development`.

## Local MCP

Set your MCP client's stdio command to the absolute path of `target/ai2sw/ai2sw.app/Contents/MacOS/ai2screenwake-mcp` in the built checkout, with no arguments. The bundled executable implements `initialize`, `tools/list`, and `tools/call`; its only tools are `is_on`, `turn_on`, and `turn_off`, each accepting an empty object. Show Log and Quit are native UI only.

Discovery never launches or enables the owner. A control connects to the existing owner or requests launch of that exact bundled app Off; it never automatically turns protection on. An unbundled development binary returns a structured unavailable error, not false Off. Results follow observed settlement, including explicit pending/error and unavailable outcomes.

When confirmed On, status includes protected-idle duration and only proven suppressed events with `epoch_ms` and `minutes_into_protected_idle`. Actual successful idle replies have separate typed native receipts, not the existing paired suppression-proof stream. An empty MCP event list means none confirmed by that stream, not proof nothing was prevented. See the [MCP contract](<code/crates/ai2screenwake_client/src/mcp/README.md>).
