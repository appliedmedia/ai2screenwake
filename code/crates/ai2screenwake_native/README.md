The user-facing assertion reason is `AI2ScreenWake explicit idle protection`. This display correction changes neither IOKit resource types/ownership nor bundle ID `com.appliedmedia.ScreenWake`, native LaunchServices validation or the `ai2screenwake-<login-session>` private directory. Launch resolves the actual selected `ai2sw.app` by URL, not a hardcoded basename.

`src/power.rs` owns both IOKit IDs: `PreventUserIdleSystemSleep` and `PreventUserIdleDisplaySleep`, acquired using `IOPMAssertionCreateWithName`. Partial acquisition rolls back; a failed release retains its ID for explicit Off retry. Repeated enable does not duplicate IDs. Success emits `Power::Assertions::Resources::Observed` with the exact request, actual count and paired clocks. Every completed failure instead emits error-first `Failed` carrying that request/count and the first actual fault, even when rollback or later timing also fails. This existing terminal shape avoids dropping the original cause into code-only or generic outcomes; no timestamp is invented. Mutexes are released before observers, including synchronous cleanup requests.

Quit must emit and observe bounded explicit Off cleanup while the bus is live. Final `Drop` only attempts best-effort OS release; it cannot report success or retry indefinitely. No strong Emitter is cached: Registry owns its native handler, so retaining one would create a cycle and prevent destruction. A destructor release failure has no live callback path; process exit remains the final OS cleanup boundary. This lifetime constraint was clarified by coordinator message `msg_20aa512637b2`.

`NativeSeam::attach(Registry)` exposes `emit(KvEnvelope) -> ()` and `observe(Arc<dyn ObservationSink>) -> ()`; the sink receives `observed(KvEnvelope) -> ()`. The integrated client FFI host and generated UniFFI/Swift attachment use this same owner. Delayed native completions use the supplied typed `Emitter`, not public raw ingress.

`src/activity.rs` samples `CGEventSourceSecondsSinceLastEventType(kCGEventSourceStateCombinedSessionState, kCGAnyInputEventType)`. It validates finite, nonnegative, representable age before converting seconds to milliseconds; source faults dispatch an attributed error before an explicit null-age observation. Every observation preserves owner/generation/episode/sample identity. Clock capture pairs real UTC with a bracketed `mach_continuous_time` sample and checked timebase conversion; that monotonic clock includes sleep. Client policy, not native sampling, resets/excludes suspended episodes. A sampling clock failure emits its explicit timing error without inventing a sample. An apply clock failure instead emits error-first `Power::Assertions::Resources::Failed(FailedApply { request, held_count, fault })`, retiring that exact completed physical operation without a clock or success claim. Preliminary timing failure prevents acquisition, never an Off release attempt. Post-acquisition failure retains both IDs; failed releases retain their actual IDs. Explicit Off/Quit can retry, while caller expiration alone never retires unfinished physical work.

Native sampling has no event tap, synthetic input, activity pulse, privileged/input-monitoring permission, preference write, or input-content logging. OS-reported input age is not a per-attempt cancellation stream. This increment emits no suppression records and does not infer them from assertions or elapsed time. Actual forced-sleep/wake product behavior, screensaver efficacy and controlled idle behavior remain unverified integration gates; display assertion documentation is not screensaver proof.

## Manual screen saver corner guard

`src/corners.rs` and `src/corners/system.rs` implement the separately authorized manual-corner guard, not an IOKit sleep veto. Production `SystemPower` supplies `SystemCorners`; explicit `PowerApi` fixtures without that collaborator exercise assertions only. The guard reads and validates the four Dock corner actions/modifier masks through public CFPreferences. The corroborated Dock schema assigns 5 to Start Screen Saver and 13 to Lock Screen; this is observed preference-schema evidence, not an Apple SDK enum. Unknown values fail explicitly. Quartz active display bounds and original event locations share logical, top-left global coordinates, including negative origins and portrait displays, without multiplying by backing scale.

A public active `kCGSessionEventTap` handles only mouse movement and drag events. It changes the original event's location out of a configured two-point saver-corner square, rather than returning NULL after the pointer may already have reached it. It never posts events, warps the pointer, captures keys, changes preferences, cancels forced sleep or stops another process. Entry is deflected regardless of saved modifiers so a later stationary modifier press cannot activate the saver there; keyboard events themselves are untouched. Activation with the pointer already in a guarded square fails explicitly. The exact Dock recognition boundary and effect of original-event modification still require the signed-app witness; direct callback/geometry tests do not establish that Dock was stopped.

On may request standard Accessibility authorization once per native owner, only when a saver corner requires it and the calling main bundle identifies `com.appliedmedia.ScreenWake`. A test/helper cannot request the app's grant. Startup, query, Off and source-health checks do not prompt. Denial, nil tap, installation failure and stale configuration fail acquisition without an idle-only successful On. The source starts unauthorized. Typed `Power::Corners::Guard::Authorize` carries the exact owner-admitted pending acquisition and revision. After both IOKit assertions are acquired, an internal bounded native handshake rechecks permission, configuration, topology, tap health and the current stationary pointer on the source thread, then activates the exact acquisition. Only its successful acknowledgement permits `Observed` and outward On. A late reply cannot arm a retired source. Later Off/Toggle/Quit observation permanently retires an existing acquisition before cleanup; Toggle while already Off does not retire the future On source. `contracts::observe_controls` must be attached before receiving owner controls; the client runtime does this beside native registration.

Apple's [WWDC 2019 security explanation](<https://developer.apple.com/videos/play/wwdc2019/701/>) explicitly distinguishes `listenOnly` from `defaultTap`: a modifying tap requires Accessibility authorization. That establishes the selected active mouse-filter method's grant, unlike the older SDK paragraph about key events alone. The code's mask is mouse movement/drag types 5, 6, 7 and 27, not keyboard events; it neither records keys nor calls `CGEventPost`. Accessibility remains broad permission. Normal IOKit idle assertions do not require it. Making corner protection optional would change the current all-capabilities On contract and is not authorized by this source correction; no permission/preflight bypass or live probe is added.

The completed separate research identifies public macOS 27+ [disableScreenCornerInteractions](<https://developer.apple.com/documentation/appkit/nsapplication/presentationoptions-swift.struct/disablescreencornerinteractions.md>): frontmost app only, with hideDock or autoHideDock, no documented full-screen requirement and broad corner suppression. No Accessibility prerequisite is documented, but no actual no-grant witness exists here. It is not a documented background saver-only lease or selected replacement for current macOS 13+ behavior. No private/global impossibility claim, focus stealing or Dock mode change follows from this research.

The runtime's native-handler collaborator also checks the actual current owner request, generation, desired/closing state and source eligibility immediately before enabled physical work. An older queued authorization cannot admit obsolete work after Off or Quit; rejection is error-first and correlated. Already-prepared sources retain their revocation fence; newer explicit On and Toggle-from-Off remain admissible. Every new native trait hook is forwarded through that collaborator.

`CornerApi::permission` returns `PermissionOutcome::Checked(result)` when no request occurred, or `Requested(result)` only after the eligible target-app request was attempted. `CornerGuard::start` spends the owner's allowance only for `Requested`, even on denial. No-saver intervals, configuration failures before permission, existing grants and ineligible callers preserve an unused allowance; Off never resets a spent allowance. Controlled `@permission_budget` scenarios cover each transition and the request-free retry, without calling live permission APIs.

The callback uses only bounded native change checks and a nonblocking authorization snapshot. Original-event modification occurs inside the same short fence that Off retires. A separate delivery thread dispatches bus events, so a slow observer cannot stop the native run-loop pump. Timeout, user disable, permission loss, relevant configuration change and display reconfiguration revoke before emitting error-first `Power::Corners::Guard::Lost`. Core invalidates On, including late acquisition acknowledgements and wake observations. `Filtered` means an actual pointer-entry deflection, with no coordinates or keyboard data; it is not an idle-cancellation proof and never enters MCP suppressed-idle arrays. Stop revokes first, signals both workers, tears down native sources on their owning thread and waits at most 500 ms without joining an unfinished worker. A timeout is a failed cleanup, not successful Off; explicit cleanup retries retain the original source. Both low-level fixture resource counts and physical IOKit counts still mean exactly two idle assertions.

The first specific loss fault is published into a single-assignment cell before the live flag is cleared or a notice is attempted; a timeout/notice race therefore retains its actual cause. Eligible movement outside a saver corner resets entry reporting without changing that event or querying displays, allowing a later entry to emit another fact. A source with no installed tap waits between checks instead of relying on an empty CF run-loop mode to delay; installed taps still pump that mode. Cleanup retry assertions require the actual latest Applied/zero-resource outcome, separately from bus-free Drop.

The selected contract is one fixed, freshly validated assignment per enabled interval, approved by coordinator message `msg_887a0e383cbc`. Public CFPreferences reads are cross-checked against the exact regular, same-user, non-symlink Dock plist. No preference synchronize/write API is called. Vnode watches cover both file and parent. On replacement, the source opens and watches the new descriptor before parsing its assignment, then rereads that same watched descriptor and verifies stable bytes/current-path identity before clearing pending. The explicit `revalidate_after_watch` local-file seam permits a deterministic owned replacement edit without touching user preferences. Unrelated files/keys or unchanged replacement resume only after these checks; relevant changes, malformed/unsafe files and unstable or over-50-ms validation fail explicitly. Display geometry is checked on the source pump and before modifying an actual corner event.

**Unverified safety boundary**: public CFPreferences and file notifications do not establish atomic ordering with Dock's in-memory preference adoption. Concurrent external reconfiguration has an unavoidable unverified interval; this is not a zero-stale guarantee. Known Lock/unknown actions are never selected, and independent explicit lock/menu/lid/thermal/forced-sleep paths are untouched. The signed-app actual-corner/config-change witness remains required. No user pointer/corner/saver/lock/sleep experiment or permission prompt was run by this worker.

## Explicit sleep/wake monitor

`Power::Activity::System::Watch` binds the source-owning native implementation's weak observation provenance; `Availability { revision, available }` uses that same typed logged bus. Production `MacPower::new` requires successful registration before acquisition. A failed poll atomically latches unavailable under the resource mutex before emitting its fault/availability; new enables fail without acquiring, while Off always attempts release. Core invalidates duration/proof intervals and rejects On until a newer registration succeeds, without auto-enabling. Source-generation guards prevent a failed monitor's late stop/callback from invalidating its replacement. Low-level injected `with_api` seams have no background-source requirement until an explicit monitor starts.

Queued interruption fan-out rechecks both source generation and acquisition identity, so work captured by an older monitor cannot escape its replacement guard.

The generated host keeps its concrete `Arc<MacPower>`, registers it through the unchanged native contracts, then calls `lifecycle::LifecycleMonitor::start(power.clone()) -> Result<LifecycleMonitor, Fault>` and retains the returned guard. Construction of MacPower alone never registers notifications or starts a thread. Startup has a one-second handshake deadline and reports registration/thread failures explicitly. Startup/shutdown faults return to the host for dispatch through its existing error path; notification allowance/clock/delivery faults dispatch `Error::Native::Activity::Occurred` through the live weak continuation.

The source registers `IORegisterForSystemPower`, attaches its owned source to a dedicated CFRunLoop and pumps at most 25ms per iteration. Following AndrewC's explicit 23:11:42 instruction, `CanSystemSleep` uses `IOCancelPowerChange` only for the current admitted native acquisition with both assertions and source/corner readiness. The captured opaque token is passed unchanged to that one reply call. Off, retired, unadmitted, stale or lost protection uses `IOAllowPowerChange`. `SystemWillSleep` is non-abortable and always uses `IOAllowPowerChange`; wake is never acknowledged. Existing sleep/wake interruptions retain their exact acquisition/count/clocks.

Private `idle_veto.rs` owns one short native reply fence, immutable request/weak provenance and an atomically retired epoch. The callback tries the fence once, never waiting on core/owner locks, Actions or asynchronous response. Only admission/retirement and immediate native replies use it; ordinary queries do not. Retirement linearizes before resource cleanup, and a late acquisition cannot re-arm an invalidated epoch. A valid wake may restore admission only to the same still-confirmed physical acquisition; source loss or actual veto failure cannot silently restore it. Corner source liveness is checked independently. This is native OS-resource authority, not a second UI/core state channel.

After an actual successful reply and native paired-clock capture, `Power::Activity::IdleSleep::Cancelled` records the exact acquisition and completion clocks. The token stays native, never logged or exported. API or timing failure dispatches `Error::Native::Activity::Occurred` before `IdleSleep::Failed`, retires veto authority and invalidates matching core protection while retaining real assertion IDs for Off/retry. No failed path invents a cancellation, time or On receipt; no new `Suppression::Evidence` entry or MCP capability is produced. Controlled `@idle_veto` notification tests use injected replies only, never actual OS sleep or IOCancelPowerChange. Both IOKit assertions remain; an idle-system veto is not a manual-saver veto or permission bypass.

Native stores only the active acquisition's `WeakEmitter` alongside the retained IDs. Off clears that context; clock failures never fabricate an occurrence; expired registries cannot be resurrected. The callback captures native accounting under its mutex, releases it, and queues delivery on a separate worker so slow/reentrant bus observers cannot delay OS acknowledgements. Delivery checks that the acquisition is still current; the core's existing request/generation guards remain authoritative for a concurrent Off/new-generation race. The bounded 32-entry queue reports overflow explicitly before its newest observation instead of silently pretending an uninterrupted history.

The host calls `monitor.stop(&mut self) -> Result<(), Fault>` during teardown, separately from bounded, bus-observed explicit Off cleanup. Stop signals both workers, removes the CF source, deregisters the notifier, closes the IOKit connection and destroys the port on the registering thread before freeing callback context. It waits at most 500ms for completion and never joins an unfinished/self thread. A stop called by its own bus observer lets that delivery thread exit after the observer returns. A long-running external observer produces an explicit timeout; retain the guard, release that observer and retry stop. Drop signals best-effort cleanup with the same bound; even on timeout, owned thread context remains alive until the thread exits, so no callback points to freed memory. A monitor does not hold a strong registry or keep MacPower alive.

`LifecycleMonitor::with_source(Arc<MacPower>, Arc<dyn NotificationSource>)` is the explicit native notification injection seam used by executable lifecycle scenarios, not a production no-op fallback. Its thread-confined `NotificationRegistration` must implement bounded `poll` and same-thread `stop`; the actual source is IOKit/CF only. SDK evidence: IOPMLib.h:127-208 requires prompt allowance for non-abortable WillSleep/idle permission and forbids acknowledgements for completed wake; IOMessage.h:131-175 supplies the corresponding messages; IOKitLib.h:159-182 defines source/port ownership.

## Local host helpers

* `identity::runtime_directory() -> Result<PathBuf, Fault>` resolves Darwin's `_CS_DARWIN_USER_TEMP_DIR` and `SessionGetInfo(callerSecuritySession)` to a canonical parent plus `ai2screenwake-<security-session-id>`. It ignores `TMPDIR` and process `getsid`, requires the current graphical login security session and unchanged real/effective UID, and creates nothing. App/MCP callers in different security sessions intentionally do not share an owner. Client IPC owns final path-length/symlink/UID/mode validation, 0700 directory creation, exclusive locks, 0600 sockets and peer authorization.
* `identity::readable_log_path()` resolves the real-UID account home with `getpwuid_r`, never HOME or shell commands, and captures one real `SystemTime` instant. `localtime_r` produces `Library/Logs/AI2ScreenWake/yyyyMMdd{DD}HHmmss_ai2sw.log` with local 24-hour time and weekday `mo/tu/we/th/fr/sa/su`. This creates no directory/file and is independent of binary/IPC identity. The host retains any failure for an explicit log query, not failed power startup.
* Rust-only `readable_log_path_in(home)` and `readable_log_path_at(home, epoch_seconds)` pair the same resolver/formatter with owned fixture roots and injected instants; no generated Swift setting or ambient override exists. Executable native calendar cases cover local midnight/date/weekday rollover, all seven weekday tokens, 24-hour noon and no file creation. Client snapshot cases cover actual isolated output/title/permissions, repeated refresh, collision preservation and deferred error-first behavior.
* `launch::launch_owner(bundle_path: &Path) -> Result<(), Fault>` accepts an absolute existing `.app` directory selected by the authenticated owner connector. It uses that exact canonical CFURL in `LSOpenFromURLSpec` with Async/DontSwitch/DontAddToRecents, without new-instance or OS error-display flags. Success means admission, not readiness or enabled protection. The caller dispatches returned startup/launch faults through its existing error path and waits for an authenticated owner; this leaf never launches an app in tests.
* `launch::OwnerLauncher: Send + Sync` exposes `fn launch(&self) -> Result<(), Fault>`. `launch::BundleLauncher::new(bundle_path: PathBuf) -> BundleLauncher` implements it by invoking the exact-bundle helper; a transport worker, not a blocking UI/core call, invokes this bootstrap port.

These are native-seam primitives, not new UI/core methods or public MCP tools. The integrated generated Swift/FFI host uses `MacPower` and the `contracts.rs` emit/observe port. The client owns policy, correlation, IPC, shutdown deadlines and episode resets; Swift only renders and forwards input.
