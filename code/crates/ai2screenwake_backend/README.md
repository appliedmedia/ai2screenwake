# Backend contracts

The `contract` feature contains the canonical wire payloads, typed action identities and in-process Actions framework. Default features are empty. There is no network server or server framework dependency in this increment.

* `src/contract.rs`: `Power::Session::{TurnOn,TurnOff,Query,Quit,Changed,Snapshot}`, native `Power::Assertions::{Apply,Observed,Failed,Rejected}`, `Power::Activity::{Sample,Observed}`, conditional `Power::Suppression::Recorded`, canonical error hierarchies, Status and native payloads.
* `src/contract/registry.rs`: `RegistryBuilder::{require,on,build}`, `Registry::emit<A>(A::Payload)`, `observe_action<A>(callback)` and `observe(Arc<dyn ObservationSink>)`. `ObservationSink::observed(KvEnvelope)` is the only raw observation shape. Private framework routing derives from the sealed action's Rust hierarchy, never a caller route/verb string.
* Every entry uses the same queue, append, observer fan-out and handler path. No callback or journal I/O holds the queue lock. Reentrant emissions and synchronous native completions enqueue behind the current entry. Configuring `RegistryBuilder::journal(Arc<dyn ActionJournal>)` selects one asynchronous dispatch actor so disk I/O never runs on emit callers; explicitly ephemeral host/test buses retain the synchronous in-process fast path, never a request/response waiter.
* `Emitter::emit<A>(payload)` continues correlation and `Emitter::error<A>(fault)` records the full failed action before error observers run. Clone a supplied emitter for delayed native completion. One instance allocator is shared across the entire chain, including nested and sibling continuations. Scoped subscriptions and weak continuations do not permanently own a disposed registry.
* `Log::Session::{Query,Snapshot}` is a native-only read-only metadata projection, including the query. Its bounded 256-entry window retains actual persistent sequence numbers and sets `earlier_entries_omitted`; `storage_error` explicitly marks append failure. Display labels avoid recursive log payloads and protected data. This is not a fourth MCP tool or UI file getter.
* `IdGeneration::next_id<A>(&payload)` is the only entity mint. SHA-256 uses two-byte big-endian UTF-8 length framing for the hierarchy/payload plus 16 random bytes; checksum chunks retain the full digest, followed by two randomizer chunks. Bus correlation counters are not stored entity identities.
* Raw native input `emit_envelope(KvEnvelope)` admits native session controls, including Toggle/Quit, and the native log query. Native observations require the injected typed callback. Authenticated IPC separately admits only the three MCP controls.

Clients depend on `default-features = false, features = ["contract"]`. Wire `_genus` and its delimiter remain implementation details; display labels and `failed_genus` are diagnostics only, never dispatch inputs. The seam does not provide direct state/log getters.

Request preparation and scoped observer lifetime live in the same registry, not a second bus. `PreparedAction<A>` is single-use metadata; `CorrelationId` is opaque and distinct from stored entity identity. Canonical eventual `Settlement`/`ControlResult`, injected `OwnerLocation` and `InterruptionObserved` are in `src/contract/session.rs`; their policy does not change native acquisition/sample payloads.

`Registry::receive_owner(KvEnvelope)` is the authenticated connector's response-only ingress: it validates typed settlements, snapshots and canonical errors, never remote commands/native outcomes. `KvEnvelope::attributed<A>(fault)` attaches only a known action type's diagnostic identity without a public route getter. Raw native UI ingress retains its separate controls-only admission rules.

Conditional cancellation proof uses `Power::Suppression::Requested(SuppressionRequest)` followed by `Recorded(CancellationObserved)`. Requested carries the original IdleRequest guard, actual native request ID, increasing sequence, eligible IdleSleepRequest kind, paired occurrence clocks and genuine idle age. Recorded must match that request and carries the actual cancellation acknowledgement ID, paired clocks, genuine occurrence idle age and explicit `cancelled` outcome. The obsolete native-computed anchor field is removed: policy anchors and offsets are exclusively core-owned. These internal types neither add MCP tools nor claim an available OS cancellation stream.

`src/contract/journal.rs` declares the first append observer and diagnostic history contract. Startup loads only the bounded tail, never dispatches historical envelopes or restores owner policy. Failed appends enter `Error::Log::Storage::Occurred`; their explicit receipt prevents native enabling work (`Power::Assertions::Rejected`, not a fake native outcome), successful control acknowledgement or healthy-looking log projection from escaping. Actual native accounting and explicit Off/Quit cleanup remain observable even when disk storage fails. Volatile attempts/errors remain in the bounded current-session diagnostic view; they never claim durable success.

`Power::Assertions::Failed(FailedApply)` is a clockless terminal native failure, distinct from never-executed `RejectedApply` and caller expiration. It carries the exact completed Apply, actual retained-resource count and previously dispatched fault, never an invented timestamp or successful resource observation. Only a matching pending operation retires; newer intent can then reconcile or an explicit retry can run. Native Off attempts release independently of clock availability; failed timing still produces an error rather than false success or Closed.
