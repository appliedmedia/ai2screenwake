# Client owner foundation

The application is displayed as AI2ScreenWake and built at `target/ai2sw/ai2sw.app`; Rust crate names, generated UniFFI names and private login-session identity stay unchanged. Rust projects the observed 24-point TV and matching 96-point preview, product/accessibility strings and read-only `ai2sw.log` view. Off selects closed eyes/smile/right Zzz, On wide eyes/gritted teeth, and attention X X/frown with `Status: Error` and no punctuation badge. All share an inset screen and left ears. Genuine faults remain latched across later status observations; accessibility names the independent observed protection, and neither core Status nor MCP/resource truth changes merely to choose artwork. Pending dots and control/termination semantics are unchanged. Swift owns only native layout/input.

On explicit `Log::Session::Query`, `FileJournal` exports metadata-only diagnostics at native-resolved `~/Library/Logs/AI2ScreenWake/yyyyMMdd{DD}HHmmss_ai2sw.log`, with local 24-hour time and lowercase weekday `mo/tu/we/th/fr/sa/su`. Native captures one instant per owner run; repeated queries refresh that stable filename, never a new file per action/open. Successful `readable_path` supplies both the actual absolute first line and Rust viewer basename. Binary `actions.journal`/`actions.previous`, lock/socket and replay remain in the existing private login-session directory.

`NativeHost.new` injects the real-UID account-home/local-time path result through Rust-only `OwnerServer::bind_with_readable_log`; no exported configuration or Swift filesystem logic is added. Default/telemetry owners and `NativeHost::with_location` derive isolated Library/Logs trees beneath their explicit private location, never the real user's Logs during tests. Resolver failure is retained for Show Log and dispatches `Error:Log:Storage:Occurred` before the failed snapshot; startup and independently healthy append/On/Off/Quit still work.

The derived directory/file require private owned 0700/0600, regular no-follow single-link files and checked identity. A create-new `.pending` sibling is written/synced and atomically published with exclusive first rename; a same-second different-run filename is refused with prior bytes preserved. Same-run refresh only replaces its recorded device/inode; unsafe/replaced targets and pending files fail explicitly. The bounded 64 KiB/200-label output remains on-demand, not live tailing/replay. No retention deletion, fallback destination, synthetic timestamp, clipboard write or path/text/payload telemetry is introduced. Actual append failure still gates durable/enabling claims independently.

`runtime::start(native: Option<Arc<dyn NativePower>>) -> Result<Registry, StartupError>` starts an explicitly ephemeral isolated OFF host/test owner. Production uses `OwnerServer::bind`, which supplies the private durable journal and returns only emit/observe access to policy. Missing native collaborators fail explicitly before startup. Register observation before emitting controls; `Power::Session::Snapshot` carries state, never an emit return value.

The implemented slice admits typed controls, serializes native applies, shares repeated pending setters, rejects mismatched completions, reconciles newer intent only after older physical work completes, and reports unknown/error for partial or failed resource convergence. Native faults enter canonical error actions before the failed projection. A query while confirmed On requests fresh native idle age and calculates floor(min(OS idle age, elapsed confirmed-On age)/1000). Sampling faults preserve independently confirmed protection and expose null duration, never fabricated zero.

`tests/features/foundation.feature` and `tests/steps/foundation.rs` exercise the real typed bus, serialized contracts and an explicitly test-only controlled native boundary. No production native implementation pretends to acquire resources. Run `cargo xtask prepare`, then `cargo xtask sanity` from the exact root; the latter verifies provenance and runs the focused scenarios with three isolated workers within 10 seconds, including setup. See [runner details](<../../xtask/README.md>).

The integrated client implements request settlement, interval/cancellation policy, private IPC, durable diagnostic history, generated FFI/menu projection, the MCP adapter and optional core telemetry. The native package owns actual OS access. External telemetry authorization/configuration/delivery, actual OS cancellation-source evidence and release remain unproved.

`src/bin/ai2screenwake-mcp.rs`, `src/mcp/`, `tests/features/mcp_*.feature` and `tests/steps/mcp_delivery.rs` are implemented and integrated. `cargo xtask check` selects the actual default/FFI/MCP/telemetry targets; `cargo xtask build --profile release` generates the production attachment and packages the app/MCP pair. Shared runtime/contracts/manifests require serialized ownership; schemas stay canonical and no fourth runtime crate is introduced.

## D3 request work

Explicit Off retires superseded waiters before capacity admission, so 128 pending queries cannot prevent native release or Quit. A newer failed wake cannot be overwritten by an older successful Apply. Idle/proof anchors share a one-millisecond sampling tolerance without restarting their protected interval; larger contradictory anchors and existing identity/clock guards still fail.

The native source publishes ordered `Power::Activity::Availability` events after `Watch` binds the same logged Actions path. Source loss invalidates live duration/proof intervals and prevents new On work in both core and native; only a newer successful monitor registration restores eligibility, never automatic reacquisition. Off/Quit preserve actual retained-resource accounting.

Source loss cannot settle a pending Off early or attach an enablement fault to normal post-Quit observer teardown. Cleanup waits for its real native zero-resource result; a spontaneous native source failure still logs its original error.

A derived Toggle consumes only its matching queued target before validation, including a rejected On. Recovery therefore never leaves a failed target latched or requires an extra click; newer queued targets remain untouched.

Concurrent native idle samples are independently keyed; a later-arriving older sample cannot rewind the shared observed projection. Every admitted control has one eventual `Power::Session::Settled` result, separate from intermediate observed Snapshots: repeated setters wait for their shared native convergence, every superseded setter gets its own error, and Quit only settles Off after explicit zero-resource confirmation. Timed-out or abandoned callers release notifications without canceling physical intent; late native results cannot complete an expired caller twice.

An older successful sample cannot disguise a newer failed observation: its ordered result retains the explicit current sampling error and null duration, independently of confirmed On resources. A sample contradicting already observed genuine activity is rejected rather than increasing duration from a retired anchor. Valid fresh native request/receipt age observations can update duration through the same logged path; no client or UI clock computes policy.

`src/projection.rs` caps retained requests/deadlines at 128 and uses one condition-variable scheduler, not per-request blocking threads or an unbounded timer queue. Waiters and deadlines hold only weak continuations. Production deadline is five seconds; `runtime::start_with_options` accepts a positive shorter test/host deadline, never a longer timeout or product preference. Expiration itself is a named logged action; it does not pretend physical work completed. Error-first `Power::Assertions::Failed` records an exact completed operation and retained-resource count without an invented clock. Only its matching in-flight operation retires, permitting explicit Off/Quit cleanup or newer-intent reconciliation; stale/duplicate failures cannot retire later work. `tests/features/runtime.feature` and `tests/steps/runtime.rs` cover this real-owner boundary, including controlled `MacPower` faults without OS assertions.

Backend `Registry::prepare<A>(payload)` reserves only opaque request metadata; `PreparedAction::correlation()` allows result interest to be registered before `emit_prepared(prepared)`. No core state is returned. `Registry::subscribe(sink)` provides a peer-lifetime subscription whose drop unregisters future callbacks; `Emitter::downgrade()` provides non-owning notification retention. Existing native emit/observe signatures remain unchanged.

`Power::Activity::Interrupted(InterruptionObserved)` accepts only the current active/in-flight enabled Apply and newer paired native lifecycle clocks. Actual WillSleep clears live interval observations and explicitly settles pending queries/setters with `system_sleep`; DidWake with both resources resets the effective-On clock so sleep time is never counted. A missing resource produces an error, not false On. Native completions racing with sleep remain pending until both acquisition and wake evidence converge; confirmed physical Off clears the old interruption even when newer intent is waiting.

The existing `IdleRequest.episode_id` remains the native acquisition guard, not a per-query or per-input ID. A separate core-only protected-idle anchor advances on genuine observed activity and wake, clearing only current-interval records. The initial proposed test demanding a new acquisition ID on every activity was rejected as over-specified before implementation: the requirement is resetting the live interval, not forcing native to learn a hidden core-policy ID.

Suppression policy is evidence-only: Requested must identify an actual eligible native idle-sleep request and Recorded must match its owner/generation/acquisition/sample/native request, acknowledge successful cancellation and preserve the same protected-idle anchor. Request order, identity and receipt checks run before any interval mutation, so stale/unmatched evidence cannot clear valid records. Failed acknowledgements and inferred assertion/timer activity create no records.

At most 64 native requests await acknowledgement; their occurrence-clock proof window is five seconds and expired evidence dispatches an explicit error. The latest 64 verified events are ordered by monotonic occurrence, with truthful truncation beyond 64; actual UTC `epoch_ms` is copied from each receipt and fractional minutes are fixed at occurrence, never recomputed at query time or from wall-clock deltas. Real activity, Off/new On, wake and restart clear the live list. Queries/repeated On preserve it; diagnostic history is separate. The real OS cancellation source is still absent, so the actual app may correctly report an empty confirmed list.

## Local owner consumer API

Cancellation now releases transport capacity through the existing typed `Power::Session::Abandoned` housekeeping event, not a fourth OwnerControl/tool, protection lease or cancellation of physical intent. Local interest is removed before same-session replacement; the authenticated peer accepts at most 32 correlations and intersects them with only its own pending IDs before logged core dispatch. Late/duplicate or foreign-peer IDs cannot remove another peer's interest. Outgoing metadata remains bounded. A late attributed error for a retired request is still observed but cannot fail unrelated pending requests; source-less protocol/framing failures remain connection-wide.

`src/ipc.rs` now supplies the actual private Unix-socket transport:

* `for_current_user(directory: PathBuf) -> OwnerLocation` binds the real UID to the directory supplied by native `identity::runtime_directory()`, without guessing a temp location.
* `OwnerServer::bind(location: OwnerLocation, native: Arc<dyn NativePower>) -> Result<OwnerServer, StartupError>` acquires the exclusive private owner and starts OFF; `actions() -> Registry` supplies the exact emit/observe port for `NativeSeam::attach`.
* `OwnerConnection::connect(location: OwnerLocation, launcher: Arc<dyn ai2screenwake_native::launch::OwnerLauncher>) -> Result<OwnerConnection, StartupError>` starts a lazy connector, not protection. The native `BundleLauncher` owns exact app selection; actual readiness is bounded separately.
* Call `connection.observe(Arc<dyn ObservationSink>)` once, reserve `connection.prepare::<Power::Session::Query>()` or either setter, register the opaque `PreparedAction::correlation()` in the consumer's request map, then `connection.emit(prepared)`. Emit returns `()`; only `Power::Session::Settled` carries eventual `Settlement { correlation, result: ControlResult { status, error } }`. Exactly Query/TurnOn/TurnOff implement `OwnerControl`; Quit and Show Log are native-only.

Native primary-click uses typed `Power::Session::Toggle(Empty)`, admitted only on the native seam. Its core handler reads the latest admitted/pending owner intent and emits typed TurnOn or TurnOff; Swift owns no toggle policy or mirrored enabled flag. A small queued-target fence keeps already queued native toggles from reading the same older intent before their derived setter messages run. Toggle does not implement `OwnerControl` and is not an IPC/MCP tool.

The transport uses the same KV envelope with a four-byte big-endian prefix, a 64 KiB body limit and 32 unsettled requests per peer. It verifies actual peer UID, private 0700 owned non-symlink directories, 0600 sockets and lock files, nonblocking exclusive `flock`, bounded socket paths and stale socket identity before removal. There are at most 16 peer workers; queues are bounded, scoped subscriptions are released on disconnect, and disconnect never reverses admitted intent. Launch/connect is limited to ten seconds and operations to five seconds; failures enter error actions before terminal results. The native launch helper is never an automatic TurnOn.

For normal host shutdown, register observation, emit native Quit and wait for typed `Power::Session::Closed(OwnerClosed { session_id, generation })` before disposing the server/host or terminating the app. Quit permanently fences this owner against later On/Toggle, including already queued derived enables; safe queries and explicit Off/Quit cleanup retries remain available. Closed is emitted only after current-generation explicit zero-resource confirmation (or the resource-free initial Off state), after terminal request settlement; a failed/expired cleanup never emits it.

Do not treat `OwnerServer::drop` or an intermediate Off snapshot as cleanup proof. Drop is nonblocking and requests the initial Quit fence only when not already closing; it never retries a failed cleanup implicitly or joins from a bus callback. Until Closed, the existing owner service and private lease remain alive, serving cleanup queries/Off retries and refusing a replacement owner; if the host incorrectly disposes early, an explicit `cleanup_pending` error records that ownership was retained. After Closed and disposal, peers drain queued responses before the service removes only its unchanged owned socket, while the lease remains tied to all surviving owner Actions ports until actual owner disposal. No per-client lease or extra MCP tool is introduced.

`ffi::observe_menu` folds both Changed and Snapshot in Rust using their owner-session revisions. Older revisions emit no rendering packet; equal revisions remain admissible for fresh query observations. The persistent-queue regression uses the actual checked private owner journal and a completion observer barrier to place Off before On-derived snapshots drain. Rendered revisions cannot regress, and final menu truth agrees with a query through the real authenticated `OwnerConnection` used by MCP. Controlled native resources keep this host test free of OS power effects; SDK protocol and packaged-app acceptance remain separate checks. Swift has no revision policy, mirrored protection state or additional channel.

## Durable diagnostic history

Foreign shutdown retains the actual disposal witness across explicit Quit retries and collects socket identity/removal errors until disposal really completes. Peer write failures are logged separately, never mistaken for unfinished endpoint disposal. Rust projects `termination_failed` on failed cleanup; AppKit denies its pending deferred termination and permits a retry, while only the existing successful terminal render approves exit. Four executable Cucumber cases in the canonical FFI/UI family exercise the private helper, including actual pending-journal dispatch through its production cleanup-error collector before disposal; library tests are supplementary.

The persistent dispatch signal owns queued work until its worker takes and drains it, but retains no registry while idle. Dropping the last ingress therefore cannot destroy a queued socket-cleanup error before observers and the disposal witness run. A canonical foundation scenario verifies final error-before-disposal ordering across 32 isolated journal actors; no producer completion or shutdown success is inferred from enqueue alone.

`src/action_log.rs` is the actual owner-locked store, created only under the verified private runtime directory. `actions.journal` and one `actions.previous` archive are each limited to 1 MiB; only the 256-entry recent tail is resident. Each version-1 record has a four-byte big-endian size, SHA-256 checksum and exact sequence/envelope JSON. Every append is synced before observers/side effects; a single dispatch actor keeps that I/O off emit callers. Rotation replaces only a verified private owned archive and retains contiguous sequence history.

Startup verifies file type, UID, 0600 mode, record bounds, version, checksum and sequence; corruption/I/O failure preserves bytes and returns an explicit startup error, never an empty success fallback. Retained history only rebuilds diagnostics: a new process starts Off, generation/session state is fresh, and no assertion, On intent, closing fence or live suppression array is replayed. Native Show Log observes canonical `LogSnapshot { entries, earlier_entries_omitted, storage_error }`, never a file read from Swift.

Both read-only candidate opens, including rotation's archive validation, are nonblocking before descriptor-based type checks, so a FIFO cannot suspend startup/dispatch. Exhausted inbound/continued correlation metadata produces a validation event without terminating dispatch.

The archive regression shares the private production storage codec, observes every persisted filler, measures active/next-frame bytes, and installs its owned FIFO before emitting the exact request that crosses the unchanged file limit. Old-open failure always has exact FIFO rescue; no public state/test getter or mirrored storage serializer is added.

Append failure permanently rejects enables and durable-success claims in that owner. Errors precede failed terminal results, and rejected native work is explicit rather than a synthetic successful seam. Actual resource accounting and explicit Off/Quit cleanup still run; even with a storage error, Closed is emitted only after actual zero-resource convergence. Thus shutdown observes physical cleanup instead of relying on either a healthy disk or Drop. The real cancellation stream remains absent and empty confirmed arrays remain honest.

`tests/features/ipc.feature` / `tests/steps/ipc.rs` exercise real private sockets, two clients plus native control, actual peer UID/mismatch, the exclusive owner lock, launch-without-enabling, malformed/oversized/forged input, disconnect without canceling intent, the 32-request limit, stale/symlink identity, fragmented frames, private modes, closing ownership, durable restart, bounded rotation and rejection of private request values from diagnostics. Runtime scenarios inject storage failures only in isolated tests and prove no enable/success/healthy-log fallback; actual persistence/replay/corruption tests use real files and sockets. Native resources remain deterministic test-only collaborators; no different-UID process or OS power witness is claimed. Run affected `cargo test -p ai2screenwake_client --test runtime --test ipc -- --concurrency 3` after separately measured `--no-run` preparation; the completed-wave `cargo xtask check` already selects these targets and their isolated feature profiles.

## Explicit local-engineering telemetry boundary

Negative HTTP/count requirements continuously accept from the real owned listener through forwarding Stopped and owner disposal, including requests pending before any explicit receive. Only the test's actual normal Quit and its single derived Off may add at most one analytics request each; disabled/invalid/report-only counts remain exact. No external collector or authorization is introduced.

`telemetry::Configuration::{Unconfigured, Disabled, Authorized(Destinations)}` is injected only into `OwnerServer::bind_with_telemetry(location, native, configuration)`. Existing constructors and the actual FFI bootstrap remain intentionally Unconfigured. Unconfigured/Disabled install the private Inactive mode, with no network worker, sending, delivery confirmation or false configuration/attention error, whether the optional feature is compiled or absent. There is no environment/file/key discovery, destination default or inferred consent. Explicit Authorized configuration still reports missing compiled transport or invalid destinations as named errors; real transport/buffer/native/log/IPC failures retain their canonical error-first paths.

The optional `telemetry` feature alone enables pinned MIT `posthog-rs =0.33.1` with all default features disabled and pinned `reqwest =0.13.2`. Default/contract/FFI/MCP/bindgen graphs do not include either. `Destinations` has optional `analytics: AnalyticsDestination { host, project_key }` and `bug_report_url`; it is deliberately not Debug/Serialize. Validate before constructing a sending client: HTTPS origins only, except explicitly injected literal-loopback HTTP; reject credentials, query, fragments, non-root analytics paths, empty keys, non-`/bug-report` report paths, and SDK normalization to another origin. Proxies and redirects are disabled; DNS uses the asynchronous hickory resolver. A project key is used only in the SDK's required authentication field, never Actions metadata, errors or logs.

One owner observer allowlists the five Query/TurnOn/TurnOff/Toggle/Quit actions and existing Native Assertions/Activity, Dispatch Validation, IPC Protocol and Log Storage error types. Network metadata contains only a fixed serialized action enum and optional recoverable boolean. No source payload, status, code/message/chain, source/runtime identity, path, input content or credentials leave this boundary. The final SDK hook removes all enrichment except those fields plus `$process_person_profile=false` and `$geoip_disable=true`; SDK-generated event UUID/time/anonymous identity are not source identities. Only recoverable=false source errors select the separately configured bug-report destination; telemetry errors/receipts are excluded, preventing feedback loops.

`src/telemetry/transport.rs` caps its queue at 32 fixed-size metadata/weak-provenance jobs plus one in flight. Backpressure and shutdown abandonment dispatch attributed `Error::Telemetry::Buffer::Occurred`, never silent drop/success. Terminal failures dispatch `Error::Telemetry::Transport::Occurred` with fixed safe messages. Local `Telemetry::Delivery::Confirmed(ForwardingReceipt { source, target })` requires an actual successful HTTP response, and SDK capture additionally requires `submitted()==1 && all_persisted()`. Source correlations remain local.

All network initialization, immediate sends and SDK Drop run on owned forwarding/service threads, never UI/Actions callbacks. The SDK creates an idle blocking background transport even in immediate mode; we never enqueue SDK captures, batch payloads, flags, replay or email. Each direct request has a one-second timeout and exactly one attempt. `Power::Session::Closed` stops admission and explicitly abandons the bounded pending queue; no draining 32 requests. The current request is allowed to finish, but no second target starts after stop. The existing owner service cleans its socket and releases its bus/lease references before joining its forwarding guard; external Actions-port ownership rules remain unchanged. `Telemetry::Session::Stopped(Empty)` is emitted after SDK/client teardown when its weak Actions context is still live. The SDK's `shutdown_timeout_ms` alone is not a hard in-flight/join bound, and OS scheduling is not a real-time guarantee; the structural guarantees are no UI wait, no native-resource dependency, no queued SDK work and no multi-request shutdown drain.

The overload witness preserves an 80-query concurrent burst and proves actual queue-full errors. It then observes every query's correlated settlement and forwarding terminal event, servicing only owned loopback I/O through a descriptor-signalled bounded barrier. This separates setup's durable journal backlog from the unchanged five-second Quit bound. A fresh query is accepted and held by the collector before Quit; monotonic event timestamps require Quit, native zero-resource acknowledgement and Closed before that request's explicit transport failure, then Stopped while the server is still owned. The response is never released, and no delivery confirmation may appear for that request. Observing the original request alone would be insufficient because its one-second HTTP deadline can expire during overload setup.
