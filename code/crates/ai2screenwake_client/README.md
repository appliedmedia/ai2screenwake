# Client owner foundation

`runtime::start(native: Option<Arc<dyn NativePower>>) -> Result<Registry, StartupError>` starts an explicitly ephemeral isolated OFF host/test owner. Production uses `OwnerServer::bind`, which supplies the private durable journal and returns only emit/observe access to policy. Missing native collaborators fail explicitly before startup. Register observation before emitting controls; `Power::Session::Snapshot` carries state, never an emit return value.

The implemented slice admits typed controls, serializes native applies, shares repeated pending setters, rejects mismatched completions, reconciles newer intent only after older physical work completes, and reports unknown/error for partial or failed resource convergence. Native faults enter canonical error actions before the failed projection. A query while confirmed On requests fresh native idle age and calculates floor(min(OS idle age, elapsed confirmed-On age)/1000). Sampling faults preserve independently confirmed protection and expose null duration, never fabricated zero.

`tests/features/foundation.feature` and `tests/steps/foundation.rs` exercise the real typed bus, serialized contracts and an explicitly test-only controlled native boundary. No production native implementation pretends to acquire resources. Run `cargo xtask prepare`, then `cargo xtask sanity` from the exact root; the latter verifies provenance and runs the focused scenarios with three isolated workers within 10 seconds, including setup. See [runner details](<../../xtask/README.md>).

This client increment implements request settlement, interval/cancellation policy, private IPC and durable diagnostic history. Native OS implementations are owned by the separate native package; generated bindings, app/UI, MCP adapter, telemetry destination, actual OS cancellation source/witness and release are not delivered by this increment.

Future MCP leaves can own `src/bin/ai2screenwake-mcp.rs`, `src/mcp/`, `tests/features/mcp_*.feature` and `tests/steps/mcp_delivery.rs`. Changes to `src/lib.rs`, root/client manifests and all runtime/contract files must be serialized through Lane 1. Do not copy schemas or create a fourth runtime crate.

## D3 request work

Concurrent native idle samples are independently keyed; a later-arriving older sample cannot rewind the shared observed projection. Every admitted control has one eventual `Power::Session::Settled` result, separate from intermediate observed Snapshots: repeated setters wait for their shared native convergence, every superseded setter gets its own error, and Quit only settles Off after explicit zero-resource confirmation. Timed-out or abandoned callers release notifications without canceling physical intent; late native results cannot complete an expired caller twice.

An older successful sample cannot disguise a newer failed observation: its ordered result retains the explicit current sampling error and null duration, independently of confirmed On resources. A sample contradicting already observed genuine activity is rejected rather than increasing duration from a retired anchor. Valid fresh native request/receipt age observations can update duration through the same logged path; no client or UI clock computes policy.

`src/projection.rs` caps retained requests/deadlines at 128 and uses one condition-variable scheduler, not per-request blocking threads or an unbounded timer queue. Waiters and deadlines hold only weak continuations. Production deadline is five seconds; `runtime::start_with_options` accepts a positive shorter test/host deadline, never a longer timeout or product preference. Expiration itself is a named logged action. `tests/features/runtime.feature` and `tests/steps/runtime.rs` are the affected target, separate from D2 compatibility; real socket correlation, episode policy and durable history remain in progress until the D3 completion receipt.

Backend `Registry::prepare<A>(payload)` reserves only opaque request metadata; `PreparedAction::correlation()` allows result interest to be registered before `emit_prepared(prepared)`. No core state is returned. `Registry::subscribe(sink)` provides a peer-lifetime subscription whose drop unregisters future callbacks; `Emitter::downgrade()` provides non-owning notification retention. Existing native emit/observe signatures remain unchanged.

`Power::Activity::Interrupted(InterruptionObserved)` accepts only the current active/in-flight enabled Apply and newer paired native lifecycle clocks. Actual WillSleep clears live interval observations and explicitly settles pending queries/setters with `system_sleep`; DidWake with both resources resets the effective-On clock so sleep time is never counted. A missing resource produces an error, not false On. Native completions racing with sleep remain pending until both acquisition and wake evidence converge; confirmed physical Off clears the old interruption even when newer intent is waiting.

The existing `IdleRequest.episode_id` remains the native acquisition guard, not a per-query or per-input ID. A separate core-only protected-idle anchor advances on genuine observed activity and wake, clearing only current-interval records. The initial proposed test demanding a new acquisition ID on every activity was rejected as over-specified before implementation: the requirement is resetting the live interval, not forcing native to learn a hidden core-policy ID.

Suppression policy is evidence-only: Requested must identify an actual eligible native idle-sleep request and Recorded must match its owner/generation/acquisition/sample/native request, acknowledge successful cancellation and preserve the same protected-idle anchor. Request order, identity and receipt checks run before any interval mutation, so stale/unmatched evidence cannot clear valid records. Failed acknowledgements and inferred assertion/timer activity create no records.

At most 64 native requests await acknowledgement; their occurrence-clock proof window is five seconds and expired evidence dispatches an explicit error. The latest 64 verified events are ordered by monotonic occurrence, with truthful truncation beyond 64; actual UTC `epoch_ms` is copied from each receipt and fractional minutes are fixed at occurrence, never recomputed at query time or from wall-clock deltas. Real activity, Off/new On, wake and restart clear the live list. Queries/repeated On preserve it; diagnostic history is separate. The real OS cancellation source is still absent, so the actual app may correctly report an empty confirmed list.

## Local owner consumer API

`src/ipc.rs` now supplies the actual private Unix-socket transport:

* `for_current_user(directory: PathBuf) -> OwnerLocation` binds the real UID to the directory supplied by native `identity::runtime_directory()`, without guessing a temp location.
* `OwnerServer::bind(location: OwnerLocation, native: Arc<dyn NativePower>) -> Result<OwnerServer, StartupError>` acquires the exclusive private owner and starts OFF; `actions() -> Registry` supplies the exact emit/observe port for `NativeSeam::attach`.
* `OwnerConnection::connect(location: OwnerLocation, launcher: Arc<dyn ai2screenwake_native::launch::OwnerLauncher>) -> Result<OwnerConnection, StartupError>` starts a lazy connector, not protection. The native `BundleLauncher` owns exact app selection; actual readiness is bounded separately.
* Call `connection.observe(Arc<dyn ObservationSink>)` once, reserve `connection.prepare::<Power::Session::Query>()` or either setter, register the opaque `PreparedAction::correlation()` in the consumer's request map, then `connection.emit(prepared)`. Emit returns `()`; only `Power::Session::Settled` carries eventual `Settlement { correlation, result: ControlResult { status, error } }`. Exactly Query/TurnOn/TurnOff implement `OwnerControl`; Quit and Show Log are native-only.

Native primary-click uses typed `Power::Session::Toggle(Empty)`, admitted only on the native seam. Its core handler reads the latest admitted/pending owner intent and emits typed TurnOn or TurnOff; Swift owns no toggle policy or mirrored enabled flag. A small queued-target fence keeps already queued native toggles from reading the same older intent before their derived setter messages run. Toggle does not implement `OwnerControl` and is not an IPC/MCP tool.

The transport uses the same KV envelope with a four-byte big-endian prefix, a 64 KiB body limit and 32 unsettled requests per peer. It verifies actual peer UID, private 0700 owned non-symlink directories, 0600 sockets and lock files, nonblocking exclusive `flock`, bounded socket paths and stale socket identity before removal. There are at most 16 peer workers; queues are bounded, scoped subscriptions are released on disconnect, and disconnect never reverses admitted intent. Launch/connect is limited to ten seconds and operations to five seconds; failures enter error actions before terminal results. The native launch helper is never an automatic TurnOn.

For normal host shutdown, register observation, emit native Quit and wait for typed `Power::Session::Closed(OwnerClosed { session_id, generation })` before disposing the server/host or terminating the app. Quit permanently fences this owner against later On/Toggle, including already queued derived enables; safe queries and explicit Off/Quit cleanup retries remain available. Closed is emitted only after current-generation explicit zero-resource confirmation (or the resource-free initial Off state), after terminal request settlement; a failed/expired cleanup never emits it.

Do not treat `OwnerServer::drop` or an intermediate Off snapshot as cleanup proof. Drop is nonblocking and requests the initial Quit fence only when not already closing; it never retries a failed cleanup implicitly or joins from a bus callback. Until Closed, the existing owner service and private lease remain alive, serving cleanup queries/Off retries and refusing a replacement owner; if the host incorrectly disposes early, an explicit `cleanup_pending` error records that ownership was retained. After Closed and disposal, peers drain queued responses before the service removes only its unchanged owned socket, while the lease remains tied to all surviving owner Actions ports until actual owner disposal. No per-client lease or extra MCP tool is introduced.

## Durable diagnostic history

`src/action_log.rs` is the actual owner-locked store, created only under the verified private runtime directory. `actions.journal` and one `actions.previous` archive are each limited to 1 MiB; only the 256-entry recent tail is resident. Each version-1 record has a four-byte big-endian size, SHA-256 checksum and exact sequence/envelope JSON. Every append is synced before observers/side effects; a single dispatch actor keeps that I/O off emit callers. Rotation replaces only a verified private owned archive and retains contiguous sequence history.

Startup verifies file type, UID, 0600 mode, record bounds, version, checksum and sequence; corruption/I/O failure preserves bytes and returns an explicit startup error, never an empty success fallback. Retained history only rebuilds diagnostics: a new process starts Off, generation/session state is fresh, and no assertion, On intent, closing fence or live suppression array is replayed. Native Show Log observes canonical `LogSnapshot { entries, earlier_entries_omitted, storage_error }`, never a file read from Swift.

Append failure permanently rejects enables and durable-success claims in that owner. Errors precede failed terminal results, and rejected native work is explicit rather than a synthetic successful seam. Actual resource accounting and explicit Off/Quit cleanup still run; even with a storage error, Closed is emitted only after actual zero-resource convergence. Thus shutdown observes physical cleanup instead of relying on either a healthy disk or Drop. The real cancellation stream remains absent and empty confirmed arrays remain honest.

`tests/features/ipc.feature` / `tests/steps/ipc.rs` exercise real private sockets, two clients plus native control, actual peer UID/mismatch, the exclusive owner lock, launch-without-enabling, malformed/oversized/forged input, disconnect without canceling intent, the 32-request limit, stale/symlink identity, fragmented frames, private modes, closing ownership, durable restart, bounded rotation and rejection of private request values from diagnostics. Runtime scenarios inject storage failures only in isolated tests and prove no enable/success/healthy-log fallback; actual persistence/replay/corruption tests use real files and sockets. Native resources remain deterministic test-only collaborators; no different-UID process or OS power witness is claimed. Run affected `cargo test -p ai2screenwake_client --test runtime --test ipc -- --concurrency 3` after separately measured `--no-run` preparation; the parallel tooling owner will add these targets to canonical xtask selection.
