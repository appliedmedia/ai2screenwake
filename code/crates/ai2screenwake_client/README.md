## D3 request work

Explicit Off retires superseded waiters before capacity admission, so 128 pending queries cannot prevent native release or Quit. A newer failed wake cannot be overwritten by an older successful Apply. Idle/proof anchors share a one-millisecond sampling tolerance without restarting their protected interval; larger contradictory anchors and existing identity/clock guards still fail.

The native source publishes ordered `Power::Activity::System::Availability` events after `Watch` binds the same logged Actions path. Source loss invalidates live duration/proof intervals and prevents new On work in both core and native; only a newer successful monitor registration restores eligibility, never automatic reacquisition. Off/Quit preserve actual retained-resource accounting.

Source loss cannot settle a pending Off early or attach an enablement fault to normal post-Quit observer teardown. Cleanup waits for its real native zero-resource result; a spontaneous native source failure still logs its original error.

A derived Toggle consumes only its matching queued target before validation, including a rejected On. Recovery therefore never leaves a failed target latched or requires an extra click; newer queued targets remain untouched.

Concurrent native idle samples are independently keyed; a later-arriving older sample cannot rewind the shared observed projection. Every admitted control has one eventual `Power::Session::Protection::Settled` result, separate from intermediate observed Snapshots: repeated setters wait for their shared native convergence, every superseded setter gets its own error, and Quit only settles Off after explicit zero-resource confirmation. Timed-out or abandoned callers release notifications without canceling physical intent; late native results cannot complete an expired caller twice.

An older successful sample cannot disguise a newer failed observation: its ordered result retains the explicit current sampling error and null duration, independently of confirmed On resources. A sample contradicting already observed genuine activity is rejected rather than increasing duration from a retired anchor. Valid fresh native request/receipt age observations can update duration through the same logged path; no client or UI clock computes policy.

`src/projection.rs` caps retained requests/deadlines at 128 and uses one condition-variable scheduler, not per-request blocking threads or an unbounded timer queue. Waiters and deadlines hold only weak continuations. Production deadline is five seconds; `runtime::start_with_options` accepts a positive shorter test/host deadline, never a longer timeout or product preference. Expiration itself is a named logged action; it does not pretend physical work completed. Error-first `Power::Assertions::Resources::Failed` records an exact completed operation and retained-resource count without an invented clock. Only its matching in-flight operation retires, permitting explicit Off/Quit cleanup or newer-intent reconciliation; stale/duplicate failures cannot retire later work. `tests/features/runtime.feature` and `tests/steps/runtime.rs` cover this real-owner boundary, including controlled `MacPower` faults without OS assertions.

Backend `Registry::prepare<A>(payload)` reserves only opaque request metadata; `PreparedAction::correlation()` allows result interest to be registered before `emit_prepared(prepared)`. No core state is returned. `Registry::subscribe(sink)` provides a peer-lifetime subscription whose drop unregisters future callbacks; `Emitter::downgrade()` provides non-owning notification retention. Existing native emit/observe signatures remain unchanged.

The registry now mints one lifetime entity identity and checked root ordinals, not an entity ID per ordinary root. `_root` follows every derived/remote envelope and opaque correlation, preserving per-prefix action and chain-wide instance counters. Native operation/session/sample IDs remain genuine separate identities. Readable logs contain four typed semantic fields plus compact separate correlation; original legacy labels are explicit history rather than invented new events.

`Power::Activity::System::Interrupted(InterruptionObserved)` accepts only the current active/in-flight enabled Apply and newer paired native lifecycle clocks. Actual WillSleep clears live interval observations and explicitly settles pending queries/setters with `system_sleep`; DidWake with both resources resets the effective-On clock so sleep time is never counted. A missing resource produces an error, not false On. Native completions racing with sleep remain pending until both acquisition and wake evidence converge; confirmed physical Off clears the old interruption even when newer intent is waiting.

The existing `IdleRequest.episode_id` remains the native acquisition guard, not a per-query or per-input ID. A separate core-only protected-idle anchor advances on genuine observed activity and wake, clearing only current-interval records. The initial proposed test demanding a new acquisition ID on every activity was rejected as over-specified before implementation: the requirement is resetting the live interval, not forcing native to learn a hidden core-policy ID.

Suppression policy is evidence-only: Requested must identify an actual eligible native idle-sleep request and Recorded must match its owner/generation/acquisition/sample/native request, acknowledge successful cancellation and preserve the same protected-idle anchor. Request order, identity and receipt checks run before any interval mutation, so stale/unmatched evidence cannot clear valid records. Failed acknowledgements and inferred assertion/timer activity create no records.

At most 64 native requests await acknowledgement; their occurrence-clock proof window is five seconds and expired evidence dispatches an explicit error. The latest 64 verified events are ordered by monotonic occurrence, with truthful truncation beyond 64; actual UTC `epoch_ms` is copied from each receipt and fractional minutes are fixed at occurrence, never recomputed at query time or from wall-clock deltas. Real activity, Off/new On, wake and restart clear the live list. Queries/repeated On preserve it; diagnostic history is separate. Native idle-reply receipts now exist separately; they do not populate this paired suppression-proof stream, so the actual app may still correctly report an empty confirmed list.

## Local owner consumer API

Cancellation now releases transport capacity through the existing typed `Power::Session::Protection::Abandoned` housekeeping event, not a fourth OwnerControl/tool, protection lease or cancellation of physical intent. Local interest is removed before same-session replacement; the authenticated peer accepts at most 32 correlations and intersects them with only its own pending IDs before logged core dispatch. Late/duplicate or foreign-peer IDs cannot remove another peer's interest. Outgoing metadata remains bounded. A late attributed error for a retired request is still observed but cannot fail unrelated pending requests; source-less protocol/framing failures remain connection-wide.

`src/ipc.rs` now supplies the actual private Unix-socket transport:

* `for_current_user(directory: PathBuf) -> OwnerLocation` binds the real UID to the directory supplied by native `identity::runtime_directory()`, without guessing a temp location.
* `OwnerServer::bind(location: OwnerLocation, native: Arc<dyn NativePower>) -> Result<OwnerServer, StartupError>` acquires the exclusive private owner and starts OFF; `actions() -> Registry` supplies the exact emit/observe port for `NativeSeam::attach`.
* `OwnerConnection::connect(location: OwnerLocation, launcher: Arc<dyn ai2screenwake_native::launch::OwnerLauncher>) -> Result<OwnerConnection, StartupError>` starts a lazy connector, not protection. The native `BundleLauncher` owns exact app selection; actual readiness is bounded separately.
* Call `connection.observe(Arc<dyn ObservationSink>)` once, reserve `connection.prepare::<Power::Session::Protection::Query>()` or either setter, register the opaque `PreparedAction::correlation()` in the consumer's request map, then `connection.emit(prepared)`. Emit returns `()`; only `Power::Session::Protection::Settled` carries eventual `Settlement { correlation, result: ControlResult { status, error } }`. Exactly Query/TurnOn/TurnOff implement `OwnerControl`; Quit and Show Log are native-only.

Native primary-click uses typed `Power::Session::Protection::Toggle(Empty)`, admitted only on the native seam. Its core handler reads the latest admitted/pending owner intent and emits typed TurnOn or TurnOff; Swift owns no toggle policy or mirrored enabled flag. A small queued-target fence keeps already queued native toggles from reading the same older intent before their derived setter messages run. Toggle does not implement `OwnerControl` and is not an IPC/MCP tool.

Before frames, the client sends the fixed four-byte `SW02` transport preface and the authenticated owner echoes it; negotiation shares one five-second deadline and observes disposal. No control body is sent until the match. A legacy owner's frame-size parser rejects this disjoint oversized length; a new owner closes a legacy connection without transmitting new fields. Both paths dispatch explicit transport failure without changing admitted protection. This bounded transport compatibility check is not a core-state RPC, new tool or storage migration; update app and packaged client together.

Thereafter transport uses the same KV envelope with a four-byte big-endian prefix, a 64 KiB body limit and 32 unsettled requests per peer. It verifies actual peer UID, private 0700 owned non-symlink directories, 0600 sockets and lock files, nonblocking exclusive `flock`, bounded socket paths and stale socket identity before removal. There are at most 16 peer workers; queues are bounded, scoped subscriptions are released on disconnect, and disconnect never reverses admitted intent. Launch/connect is limited to ten seconds and operations to five seconds; failures enter error actions before terminal results. The native launch helper is never an automatic TurnOn.

For normal host shutdown, register observation, emit native Quit and wait for typed `Power::Session::Protection::Closed(OwnerClosed { session_id, generation })` before disposing the server/host or terminating the app. Quit permanently fences this owner against later On/Toggle, including already queued derived enables; safe queries and explicit Off/Quit cleanup retries remain available. Closed is emitted only after current-generation explicit zero-resource confirmation (or the resource-free initial Off state), after terminal request settlement; a failed/expired cleanup never emits it.

Do not treat `OwnerServer::drop` or an intermediate Off snapshot as cleanup proof. Drop is nonblocking and requests the initial Quit fence only when not already closing; it never retries a failed cleanup implicitly or joins from a bus callback. Until Closed, the existing owner service and private lease remain alive, serving cleanup queries/Off retries and refusing a replacement owner; if the host incorrectly disposes early, an explicit `cleanup_pending` error records that ownership was retained. After Closed and disposal, peers drain queued responses before the service removes only its unchanged owned socket, while the lease remains tied to all surviving owner Actions ports until actual owner disposal. No per-client lease or extra MCP tool is introduced.

`ffi::observe_menu` folds both Changed and Snapshot in Rust using their owner-session revisions. Older revisions emit no rendering packet; equal revisions remain admissible for fresh query observations. The persistent-queue regression uses the actual checked private owner journal and a completion observer barrier to place Off before On-derived snapshots drain. Rendered revisions cannot regress, and final menu truth agrees with a query through the real authenticated `OwnerConnection` used by MCP. Controlled native resources keep this host test free of OS power effects; SDK protocol and packaged-app acceptance remain separate checks. Swift has no revision policy, mirrored protection state or additional channel.

Each direct request has a one-second timeout and exactly one attempt. `Power::Session::Protection::Closed` stops admission and explicitly abandons the bounded pending queue; no draining 32 requests. The current request is allowed to finish, but no second target starts after stop. The existing owner service cleans its socket and releases its bus/lease references before joining its forwarding guard; external Actions-port ownership rules remain unchanged. `Telemetry::Session::Worker::Stopped(Empty)` is emitted after SDK/client teardown when its weak Actions context is still live. The SDK's `shutdown_timeout_ms` alone is not a hard in-flight/join bound, and OS scheduling is not a real-time guarantee; the structural guarantees are no UI wait, no native-resource dependency, no queued SDK work and no multi-request shutdown drain.

Canonical public source: [SDK manifest](<https://docs.rs/crate/posthog-rs/0.33.1/source/Cargo.toml.orig>), [options](<https://docs.rs/crate/posthog-rs/0.33.1/source/src/client/mod.rs>), [transport lifetime](<https://docs.rs/crate/posthog-rs/0.33.1/source/src/client/transport.rs>), [post-enrichment hook order](<https://docs.rs/crate/posthog-rs/0.33.1/source/src/client/v0_capture.rs>) and [terminal receipt semantics](<https://docs.rs/crate/posthog-rs/0.33.1/source/src/client/summary.rs>). These were opened before implementation, not inferred from the shutdown option.

Prepare with `cargo test --locked -p ai2screenwake_client --features telemetry --test telemetry --no-run`, then run `cargo test --locked -p ai2screenwake_client --features telemetry --test telemetry -- --concurrency 3 --color never`. The executable requirements use actual owned ephemeral loopback TCP endpoints and the real SDK/HTTP clients, not a production transport mock. No external post or consent/configuration/release gate is proved by those local tests.

Forwarding uses that same preferred-local/owned-short-root helper with its existing `o/owner.sock` suffix; its controlled long-checkout case still binds a real isolated owner. Production UID/mode/path/peer validation, native isolation and HTTP/count/cleanup assertions are unchanged.

The overload witness preserves an 80-query concurrent burst and proves actual queue-full errors. It then observes every query's correlated settlement and forwarding terminal event, servicing only owned loopback I/O through a descriptor-signalled bounded barrier. This separates setup's durable journal backlog from the unchanged five-second Quit bound. A fresh query is accepted and held by the collector before Quit; monotonic event timestamps require Quit, native zero-resource acknowledgement and Closed before that request's explicit transport failure, then Stopped while the server is still owned. The response is never released, and no delivery confirmation may appear for that request. Observing the original request alone would be insufficient because its one-second HTTP deadline can expire during overload setup.

The all-settlements predicate decodes each observed envelope once per condition-variable check and compares the successful-On correlation set against all eighty requested IDs. It must not repeatedly deserialize the same growing log for each ID while holding the observation mutex, which delays the producer it is waiting for. Missing, failed or non-On settlements still fail under the unchanged five-second bound; burst size, overload, real held HTTP, Quit ordering and all production scheduling/privacy behavior remain unchanged.
